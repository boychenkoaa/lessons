## Оценка решений относительно эталона

| № задачи | Краткое описание | Оценка | Краткое пояснение, что не так |
| --- | --- | --- | --- |
| `1` | Спагетти / базовая реализация | Сделано не то / идея не понята | Вместо прямолинейного решения сразу началась архитектурная заготовка под команды и ООП |
| `2` | Процедурный стиль | Неоправданное переусложнение | Процедурная идея понята, но решение уже тянет на маленький framework, а не на простой процедурный образец |
| `3` | ООП | Точное попадание | Есть отходы в сторону внешнего интерпретатора и команд, но ядро идеи схвачено правильно |
| `4` | Модульный стиль | Неоправданное переусложнение | Вместо простого разбиения на модули построена отдельная слоистая архитектура |
| `5` | Хипстерский API | Оправданное переусложнение / осознанный выход за границы задачи | Вместо эталонного API поверх `pure_robot` спроектирован более общий клиентский API и язык программ |
| `6` | Stateless-архитектура | Сделано не то / идея не понята | Понята общая мысль про вынесение состояния, но потеряна ключевая эталонная схема с очередью, воркерами и агентами |
| `7` | DI | Точное попадание | DI по сути реализован верно, просто без эталонного акцента на формальный интерфейсный слой |
| `8` | ФП-DI | Точное попадание | Идея функциональной инъекции зависимостей воспроизведена корректно |
| `9` | ФП-DI-2 | Неоправданное переусложнение | Одна функция-инъекция есть, но концептуально решение всё ещё опирается на старую пятифункциональную схему |
| `10` | Конкатенативный стиль | Сделано не то / идея не понята | Вместо стековой интерпретации получился адаптер синтаксиса к прежнему API |
| `11` | Монада состояния | Точное попадание | Основной state-pipeline понят, даже если value-часть монады используется слабо |
| `12` | Command | Сделано не то / идея не понята | Получилась другая композиционная техника, а не явная реализация Command-паттерна |
| `13` | Event Sourcing | Точное попадание | Идея событийного восстановления состояния реализована по существу правильно |
| `14` | Stream Processing | Оправданное переусложнение / осознанный выход за границы задачи | Базовая идея понята, но решение ушло в более тяжёлую и инфраструктурную систему, чем требовалось |
| `15` | Ошибки в state pipeline | Точное попадание | Ошибки встроены в пайплайн осмысленно, отличия уже вторичны |
| `16` | AST | Точное попадание | Программа как данные и интерпретация AST поняты правильно |
| `17` | ADT | Неоправданное переусложнение | Вместо дисциплинированного ADT-решения добавлены фабрики и DSL-слой сверх сути упражнения |
| `18` | Capability-based API | Оправданное переусложнение / осознанный выход за границы задачи | Идея capability уловлена, но поднята на более абстрактный уровень capability-монады |
